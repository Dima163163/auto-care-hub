# Финальная репетиция ролей и сценариев — 26 сентября 2026

## Что проверено

Браузерный прогон выполнен на `http://127.0.0.1:4173` в Vite mock-режиме. Использованы обычное окно Chrome, инкогнито и отдельное окно Codex In-app Browser: клиент, владелец сервиса, назначенный модератор (`admin`) и Super Admin. Три обычных окна Chrome делят один профиль и cookie; для одновременных независимых ролей нужны разные профили/инкогнито.

- Клиент: поиск, фильтр рейтинга, пустая выдача и очистка фильтров, избранное, заявки/переписка. В жалобе на сообщение проверены пояснение о чтении всей переписки и вложений, согласие, отмена без отправки, подача жалобы и блокировка новых сообщений/удаления на время рассмотрения.
- Владелец: список заявок и переписок; при активном разбирательстве UI блокирует отправку и удаление. Копирование и локальное скрытие остаются доступны. API-тест проверяет запрет встречной жалобы в активном деле.
- Super Admin: поиск синтетического отчёта `chat-report-demo-1`, назначение Moderator Alex с причиной. Карточка осталась в статусе `Pending`; решение и блокировка не выполнялись. Старый отчёт без привязки к сообщению не назначается на чтение треда.
- Модератор: после назначения открыт read-only чат, видны три текстовых сообщения; открытие не помечает сообщения прочитанными участниками. Отправка от имени модератора недоступна. Время доступа в UI было указано до 27 сентября 2026, 17:10 (Самара).
- Запись к сервису: проверены доступные часы по расписанию и часовому поясу сервиса, локальная заявка и передача времени в очередь владельца. В браузере больше не предлагаются уже прошедшие часы.
- Дашборд Admin: после полной перезагрузки очереди загрузились; ошибки, появившиеся сразу после HMR, исчезли. Операционная панель была компактной по умолчанию.

## Исправлено в этом проходе

1. **Просроченные слоты записи.** Mock discovery и availability теперь рассчитывают `nextSlot` и интервалы по часовому поясу, расписанию, исключениям и уже прошедшему времени. Mock API также отклоняет прошлый или недоступный слот при прямой отправке и проверяет филиал заявки. См. [handlers.ts](../../src/app/mocks/handlers.ts#L109) и тесты в [handlers.service-request.test.ts](../../src/app/mocks/handlers.service-request.test.ts#L16).
2. **Ложный отказ панели операций роли Admin.** UI и production API допускают роль `admin`, но mock endpoint разрешал сводку только Super Admin и показывал `Backend unavailable`. Mock-граница выровнена с API-контрактом; клиенту по-прежнему возвращается `403`. Проверка: [handlers.operations-overview.test.ts](../../src/app/mocks/handlers.operations-overview.test.ts#L12).
3. **Плавающая панель не должна раскрываться сама.** Подробности теперь появляются только по действию администратора; компактный статус остаётся видим. Это уменьшает перекрытие, но не убирает его полностью. Проверка: [SuperAdminOperationsRail.test.tsx](../../src/widgets/super-admin-operations/SuperAdminOperationsRail.test.tsx#L137).

## Оставшиеся замечания

### 1. P2 — Плавающая панель операций перекрывает данные

В компактном состоянии панель всё ещё занимает нижний правый угол и закрывает часть карточки метрик на админ-дашборде; в чате она также лежит поверх содержимого. Это заметно на фактическом окне Chrome 735 × 1080. Предложение **02** переносит статус под шапку приложения; кодовый макет пока не менялся. См. [README визуальных предложений](../design/proposals/2026-09-26-final-pass/README.md) и [концепт 02](../design/proposals/2026-09-26-final-pass/02-operations-status-strip-after.png).

### 2. P2 — Mock-статус нельзя считать проверкой реального backend

Браузер работал с `VITE_API_MODE=mock`. Mock возвращает синтетическое `Critical dependencies are healthy`; этот зелёный статус не подтверждает доступность приложения, схемы БД или worker. Среди контейнеров Docker были PostgreSQL и Redis, отдельного контейнера API AutoCare Hub в списке не было. Проверка реального API/БД и интеграции здесь не выполнялась.

### 3. P2 — HMR сбрасывает временную mock-модерацию

После изменения handlers Vite HMR сбросил назначение, срок доступа и локально созданное тестовое состояние. Назначенный модератор больше не мог открыть дело; интерфейс показал, что доступ истёк или не назначен. Вход в роли сохранился, но in-memory отчёт нет. Повторно не назначал модератора, чтобы не начинать новое 24-часовое окно без дополнительного подтверждения. Для устойчивой репетиции нужен API/БД либо сохранение mock-case в устойчивом тестовом хранилище.

### 4. P2 — Не выполнен стресс-набор из 20–30 пользователей и 5–10 новых сервисов

В имеющихся fixtures отображаются 7 пользователей и 103 профиля сервисов. Они позволяют проверить выдачу и основные роли, но это не создание 5–10 новых профилей и не прогон на 20–30 аккаунтах. В `/admin/users` доступно создание администратора для Super Admin, но нет создания клиента; обычная регистрация заканчивается принятием пользовательского соглашения. Поэтому новые клиентские аккаунты из админской роли не создавались и юридическое соглашение за тестовых пользователей не принималось.

### 5. P2 — В назначенном примере не было вложений

Разрешённый синтетический тред содержал три текстовых сообщения, но ни одного видимого вложения. Доступ к переписке проверен, путь просмотра приватного вложения и истечение доступа к файлу не проверены. Для этого сценария нужен отдельный локальный тестовый attachment без реального пользовательского файла.

### 6. Проверка false-positive, не решение по делу

Seed-отчёт имеет категорию `Harassment`, но привязанное сообщение — вежливый ответ о проверке VIN. Это годится для проверки того, что жалоба не приводит к автоматическому наказанию и модератор смотрит контекст. Я не разрешал и не отклонял этот отчёт; блокировки участникам не применялись.

## Продолжение исправлений — 26 сентября 2026

### Выполнено

1. **Убрано перекрытие панели операций.** Индикатор перенесён из плавающего угла в обычный поток под шапку Admin/Super Admin. Подробности раскрываются там же и больше не закрывают карточки или чат.
2. **Mock health больше не выдаёт себя за реальное состояние.** В mock-режиме панель показывает янтарный статус `Mock mode · real backend not checked`, бейдж `Mock` и явное предупреждение, что API, БД и worker не проверялись. Визуально успешный mock-ответ не может выглядеть как подтверждённая проверка production.
3. **Сохранено одно синтетическое назначение при HMR.** Для локального демонстрационного отчёта `chat-report-demo-1` назначение и время истечения восстанавливаются из ограниченной схемой записи `localStorage`. Просроченные и некорректные записи игнорируются, решение по делу очищает сохранение. Другие mock-изменения и тестовые отчёты по-прежнему остаются in-memory.
4. **Добавлен путь приватного синтетического вложения.** Новый тестовый PNG явно помечен `SYNTHETIC QA`; отдельный тестовый отчёт проверяет чтение вложения назначенным модератором и отказ после истечения доступа. После истечения назначение скрывает сам тред и возвращает `404`. Тест закрывает только созданный им синтетический отчёт и не изменяет `chat-report-demo-1` и не применяет блокировки.

### Проверка локального API

API запущен только на `127.0.0.1:4000`; endpoint `/health` вернул `503 degraded`. PostgreSQL доступен, Redis отмечен `skipped / not_configured`, storage — `ok`, а outbox содержит 126 dead-letter событий. Эта проверка подтверждает, что локальный backend не полностью здоров; накопившиеся записи очереди не очищались и не повторялись автоматически. В mock-режиме это состояние теперь явно не маскируется. Для исправления реального backend нужно настроить его Redis и отдельно разобрать причину dead-letter событий.
